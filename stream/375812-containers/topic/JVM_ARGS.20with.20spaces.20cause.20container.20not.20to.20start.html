Oliver Bertuch (Sep 24 2026 at 19:41):

For those reading or searching around here, this was the original question:

Start gdcc/dataverse with JVM_ARGS containing a system property that has a space in the value.

For example:

-Ddataverse.pid.providers=fake -Ddataverse.pid.default-provider=fake -Ddataverse.pid.fake.type=FAKE -Ddataverse.pid.fake.label="Fake DOI Provider"
* When does this issue occur?

When using the docker container gdcc/dataverse, if JVM_ARGS contains system properties that have spaces, the container fails to start. I suspect it is the way JVM_ARGS is being interpolated in one of the startup scripts in the gdcc/dataverse container.

Here's my answer:

  • Please do not use JVM_ARGS with PID provider options. These options are already using MPCONFIG, so you can use any of the methods extensively described in the guides on how to set those (env vars, files, ...). Our Docker Compose files have some examples. That should eliminate any escaping business from 2. for good.
  • The reason your quotes don't work are due to the fact how the variable is forwarded to the JVM. By the time the JVM receives the arguments, the quotes are gone - Bash has had them for lunch. So you'd need to escape them as \" if you really want to stick with the JVM_ARGS way.
