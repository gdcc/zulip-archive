Ash Manda (Sep 08 2026 at 15:46):

Just to re-iterate on the idea that I had: Whenever a bug gets fixed right, especially critical bugs that people encounter in production, if a test isn't included with the PR, there's no way to know if that bug will just regress and reoccur in the future. So I wanted to come up with some kind of frictionless process, where critical bugs can be put into a backlog so that someone (for JSF, me) can write tests and make sure it doesn't occur again. Or request tests for critical paths that don't exist yet.

The Google Doc that I'm maintaining on UNC's behalf: https://docs.google.com/document/d/1AFNDZvNWDa-TG5G6Mu9AiwBcjmfEiyMsyFgabostj4w/edit?usp=sharing

UNC's fork where I'm writing these new tests: https://github.com/uncch-rdmc/dataverse-jsf-tests
