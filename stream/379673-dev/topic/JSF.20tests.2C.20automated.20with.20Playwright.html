Oliver Bertuch (Sep 10 2026 at 15:08):

Let me be bold and suggest some improvements: it would be even much better if these tests would...

  1. ... be part of the regular chain (unit, integration, API + JSF).

    • The container images are built three times now: as part of the normal Maven chain, as part of the API tests and as part of the JSF tests. The compute time may be better spent only doing this once. (It takes about 32 minutes to see results)
    • By instrumenting the backend code, we could add more test coverage to the reports which also get sent to SonarCloud. We can save the instrumented code in container images at GHCR, so no re-instrumentation is necessary.
    • We should probably also figure out a better "overarching" test infrastructure where things are easier to understand what trigger which other tests, what relies on what etc. Things are quite all over the place at the moment, which causes some of the redundancies to appear.

  2. ... be easier to correlate. A failing frontend test and what may have gone wrong in the backend need to be put together manually. I understand this is a deep deep rabbit hole, but maybe it's worth looking into options how to make OpenTelemetry spans from Playwright propagate to the backend so we have end-to-end snapshots?

  3. ... have a nicer web UI access for their reports. Downloading the Playwright reports is slooooow and the ZIP is largeish. (1MB/s throughput, 118MB zipfile). Can we upload these HTML reports somewhere else?

    • Also, the traces in the report require looking at these things via http:// or https//, probably due to Javascript & Browser security issues. Opening them locally via file:// denies access to them.
    • I'm aware that OpenTelemetry is probably going to influence these things.
